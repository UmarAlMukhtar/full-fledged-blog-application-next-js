# Blog Application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a polished, SSR Next.js blog with searchable posts, dynamic article pages, accessible SEO-ready UI, screenshots, and public GitHub/Vercel links.

**Architecture:** Use the App Router with a shared server-only post data module that validates MockAPI responses and falls back to local seed posts. API routes share that module; server pages render content and dehydrate the homepage query into TanStack React Query for client-side search.

**Tech Stack:** Latest stable Next.js, TypeScript, Tailwind CSS, TanStack React Query, GitHub, Vercel, Playwright/browser inspection.

**Spec:** `docs/superpowers/specs/2026-11-13-blog-app-design.md`

## Global Constraints

- Use the current stable Next.js release with the App Router and Tailwind CSS.
- Seed a small set of complete sample posts in the project so the app works immediately.
- A single server data module reads a configured MockAPI-compatible endpoint when available and falls back to the seed content when it is not configured or unavailable.
- Validate records at this external-data boundary and handle missing posts as not found.
- Search filters the hydrated list immediately without another request.
- Add `/api/posts` and `/api/posts/[slug]` as app API routes backed by the same data module.
- Set site-wide title templates, descriptions, canonical metadata, Open Graph metadata, and per-post metadata.
- Include a README with local setup, mock API environment configuration, architecture notes, and Vercel deployment steps.
- Capture homepage and individual-post screenshots in `outputs/` after verification.
- Do not add a separate test framework for this first version.

## Review Focus

- Unavailable or malformed MockAPI data should fall back to valid seed content — inspect with the endpoint unset and an invalid endpoint response (data task).
- An empty post list or a query with no matches should produce a clear, accessible empty state — inspect the homepage (home/search task).
- Unknown slugs should return the framework not-found response — inspect a fabricated slug (article task).
- Missing or malformed optional post fields should not break rendering — inspect an incomplete API record (data task).
- Long titles and narrow screens should remain readable and operable by keyboard — inspect at mobile width and tab through search/cards (UI task).
